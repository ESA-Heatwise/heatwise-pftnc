# PFTNC EOAP

This repository contains an EOAP (Earth Observation Application Package) 
for running PFTNC inference with `xcengine` and `cwltool`.

The EOAP packages the inference notebook, its runtime environment, the PFTNC
runtime source, and a CWL interface. It consumes a input dataset and a 
packaged PFTNC model bundle, then writes inference results as a STAC catalog.

## Prerequisites

Install and activate an environment containing `xcetool`, `cwltool`, and Docker.

The PFTNC repository must be checked out beside this repository because the 
notebook includes it using:

```python
build_includes=["../../pftnc"]
```

The expected layout is:

```text
workspace/
├── pftnc/
└── heatwise-pftnc/
```

The inference pipeline performs feature engineering itself, so the EOAP only 
requires a CSV input containing the required source columns shown below:

```python
['site',
 'date',
 'time',
 'site_lat',
 'site_lon',
 'chime_diatoms_ug_per_l',
 'chime_cyanobacteria_ug_per_l',
 'chime_others_ug_per_l',
 'lstm_lswt_c',
 's2_chl_ug_per_l',
 's2_tur_mg_per_l',
 's2_cdom_1_per_m',
 's3_chl_ug_per_l',
 's3_tur_mg_per_l',
 's3_cdom_1_per_m',
 'diatoms_ug_per_l',
 'cyanobacterial_ug_per_l',
 'others_ug_per_l']
```

Before running the EOAP, convert the relevant source data to CSV and place 
it under this repository's root `input/<your-site>` directory. Recreate the 
input structure exactly as follows:

```text
input/<your-site>/
├── catalog.json
├── pftnc_<your-site>_item.json
└── inference_input.csv
```

The files must refer to one another as follows:

```text
catalog.json
└── item link: ./pftnc_<your-site>_item.json
    └── asset "<your-site>": ./inference_input.csv
```

Thus, `catalog.json` refers to the STAC item, and 
`pftnc_<your-site>_item.json` refers to the actual CSV 
through its `assets.<your-site>.href` field. Keep all three files in 
the same directory and use relative paths as shown. The input directory 
must contain `catalog.json`, and the catalog must refer to the dataset 
asset using paths that remain valid when the directory is mounted into 
the container.

## Build the EOAP

Run this command from the `eoap/` directory:

```bash
xcetool image build pftnc_inference.ipynb -e environment.yml -a pftnc.cwl -b ../app/
```

The `-b` directory is generated by `xcetool` and is used as the Docker build
context. If `app/` already exists, remove it only if it is disposable, or use
a different directory. Do not accidentally overwrite an existing build context 
containing changes you need.

## Run the EOAP

Run this from the root of this repository:

```bash
cwltool --outdir testcwl/ eoap/pftnc.cwl#pftnc_inference --input_dataset_path input/elbe_bunthaus
```

`--outdir` is optional. It controls where the generated STAC catalog and 
inference outputs are collected.

The EOAP also accepts the other CWL inputs declared in `eoap/pftnc.cwl`, 
including the model bundle, inference mode, selection, and start date.

If inference reports `Cannot compare tz-naive and tz-aware datetime-like objects`, normalize the input time column while preparing the CSV. The preparation notebook converts timestamps to UTC and removes timezone information for compatibility with the current PFTNC inference implementation.
